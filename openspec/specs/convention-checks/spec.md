## Requirements
### Requirement: Branch names are validated where they cannot be bypassed

The pipeline SHALL validate the source branch name of every pull request against
the Conventional Branch rules documented in `CLAUDE.md`.

#### Scenario: A branch does not follow the convention

- **WHEN** a pull request is opened from a branch whose name lacks a valid type
  prefix or uses characters the convention forbids
- **THEN** the pipeline fails and reports the offending name

#### Scenario: The pull request build reads the right branch

- **WHEN** the pipeline validates a branch name on a pull request build
- **THEN** it reads the pull request source branch, not the merge ref, so the
  check cannot pass vacuously

#### Scenario: A local hook was bypassed

- **WHEN** a contributor pushes a branch using `--no-verify` or from a clone where
  `prepare` never ran
- **THEN** the pipeline still rejects a non-conforming branch name

### Requirement: Commit messages are validated

The pipeline SHALL validate every commit message introduced by a pull request
against the Conventional Commits rules documented in `CLAUDE.md`.

#### Scenario: A commit subject does not follow the convention

- **WHEN** a pull request contains a commit whose subject has no valid type, runs
  past the length limit, or ends with a period
- **THEN** the pipeline fails and reports the offending subject

#### Scenario: Merge and revert commits

- **WHEN** a pull request contains a commit generated by git for a merge or a
  revert
- **THEN** the check accepts it, since its format is not authored

### Requirement: The commit that lands on the trunk is validated

The pipeline SHALL validate the pull request title against the same rules it
applies to commit subjects. Pull requests are squash merged, so the commit
written to `main` takes its subject from the title rather than from any commit
a hook has seen.

#### Scenario: The pull request title does not follow the convention

- **WHEN** a pull request has conforming commits but a title that does not follow
  Conventional Commits
- **THEN** the pipeline fails, because the title is what `main` will record

#### Scenario: The squash commit is assembled

- **WHEN** a pull request is squash merged
- **THEN** the resulting commit takes its subject from the pull request title and
  its body from the description, so the convention survives the merge

### Requirement: Local and CI enforcement share one implementation

The pipeline SHALL invoke the same scripts the git hooks invoke. The rules MUST
NOT be expressed a second time in the pipeline definition.

#### Scenario: A convention changes

- **WHEN** the branch or commit rules are updated in the check scripts
- **THEN** local hooks and the pipeline both enforce the new rules, with no
  second definition to update

#### Scenario: The check scripts are run directly

- **WHEN** a contributor runs a check script against a branch name or message
  file
- **THEN** it reports the same verdict the pipeline would
